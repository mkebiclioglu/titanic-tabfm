# CLAUDE.md

## Project goal

This repo is meant to evaluate Google Research's TabFM on simple tabular prediction tasks.

The first task is a classification benchmark on the Titanic dataset.

The goal is to compare:

1. A strong traditional baseline: XGBoost.
2. TabFM using the official Google Research implementation.
3. A simple final report explaining the result.

Keep the repo focused, simple, and reproducible.

## First milestone

Build a Titanic survival classification benchmark.

The benchmark should answer:

> How does zero-shot TabFM perform against a straightforward XGBoost baseline on the Titanic dataset?

Use the same train/test split for both models.

Do not over-engineer the benchmark.

Do not add many models yet.

Do not use PyCaret for the first version unless explicitly asked later.

## Important rules

* Keep commits simple and focused.
* Do not sign commits or files as Claude.
* Do not add “Generated by Claude” or similar language.
* Work inside a project virtual environment.
* Do not run Python, pip, tests, notebooks, or benchmarks unless the virtual environment is active.
* Do not install packages globally.
* Do not invent benchmark results.
* If something fails, write down the failure clearly.
* Prefer simple scripts over notebooks.
* Prefer readable code over clever abstractions.

## Environment

Use a local virtual environment.

Example:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Before running anything, confirm the environment is active:

```bash
which python
python --version
```

The Python path should point inside `.venv`.

## Benchmark requirements

For the Titanic benchmark:

* Use a reproducible train/test split.
* Use the same split for XGBoost and TabFM.
* Use the same target column for both models.
* Avoid target leakage.
* Keep preprocessing simple.
* Save benchmark results to a results file.
* Generate a simple Markdown report.

The report should include:

* What was tested.
* Dataset used.
* Train/test setup.
* XGBoost performance.
* TabFM performance.
* Short interpretation.
* Caveats.
* Next steps.

## Metrics

For classification, report at least:

* Accuracy
* ROC AUC
* F1
* Precision
* Recall

Use ROC AUC as the main comparison metric if probability outputs are available.

## XGBoost baseline

Use XGBoost as the main traditional ML baseline.

Start with a reasonable default configuration.

Do not do heavy hyperparameter tuning in the first version.

If tuning is added later, clearly separate:

```text
xgboost_default
xgboost_tuned
tabfm_default
```

## TabFM benchmark

Use the official TabFM implementation.

The core claim being tested is zero-shot or no-fine-tuning tabular prediction.

Do not fine-tune TabFM in the first benchmark.

If TabFM setup or inference is difficult, document the issue clearly instead of faking results.

## Output files

Create simple outputs such as:

```text
results/xgboost_titanic_metrics.csv
results/tabfm_titanic_metrics.csv
results/combined_titanic_benchmark.csv
reports/titanic_benchmark_report.md
```

Exact file structure is flexible, but the repo should be easy to run and understand.

## Suggested commands

The exact implementation is flexible, but aim for commands like:

```bash
python -m src.run_xgboost_titanic
python -m src.run_tabfm_titanic
python -m src.generate_report
```

or a single command like:

```bash
python -m src.run_titanic_benchmark
```

Keep the command surface simple.

## Report tone

Be honest and plainspoken.

Good:

```text
On this Titanic benchmark, XGBoost achieved X and TabFM achieved Y. This is an initial smoke test and should not be treated as a full validation of TabFM's broader claims.
```

Avoid:

```text
TabFM is proven better than traditional ML.
```

Avoid:

```text
This fully validates Google's claims.
```

Titanic is only a first benchmark.

## Development style

Let implementation details emerge naturally.

Do not over-plan the repo.

Start by making one benchmark work end-to-end.

Then improve structure only when needed.

Recommended sequence:

1. Set up repo basics.
2. Add Titanic data loading.
3. Add XGBoost benchmark.
4. Add TabFM benchmark.
5. Save combined results.
6. Generate simple report.
7. Add README instructions.

Each step should be a small commit.
